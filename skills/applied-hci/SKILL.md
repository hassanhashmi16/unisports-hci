# Applied Human Computer Interaction

Use the course's language, examples, and evidence to explain and evaluate UI/UX decisions. Work from the user's approved product, users, tasks, platform and deliverable. Ask when an unresolved decision would change what gets built or where it runs. The project scope is frontend only. A prototype may demonstrate representative states with local or mock data when the user authorizes it. Describe simulated interactions accurately.

## Instructor emphasis

Start design decisions and reviews of key user flows with **Norman's principles**. Apply visibility, feedback, constraints, mapping, consistency, and perceived affordances. When a task is difficult, use Norman's seven principles and the gulfs of execution and evaluation to identify where users might miss an action, form a mistaken expectation, or misunderstand the result. For consequential decisions, name the principle, point to the specific screen or behavior, and explain how it helps the user complete the task.

Bring in **Shneiderman, Theo Mandel, Nielsen, the five screen-layout principles, usability and UX goals, and universal design** wherever they clarify a design choice or reveal a problem. Use the Phase 4 rubric and workbook for the full evaluation.

## Apply the interaction design lifecycle

1. **Discover and define.** Identify direct users and other stakeholders, goals, current tasks, and the physical, social, organizational and technical context. Use observed behaviors or user research to substantiate needs. Distinguish the evidence, an inference from it, and a hypothesis still to test. Select research methods to answer specific questions. Obtain suitable consent, collect only the required information, and pilot the study.
2. **Make requirements testable.** Capture functional, data, environmental, user, usability and UX requirements as applicable. Record source, rationale and a fit criterion when they help verify a decision. Use evidence-based profiles and a small persona set with a primary persona. Use scenarios to show the user's context and goal. Capture alternative or error branches in use cases and flow diagrams.
3. **Develop and evaluate alternatives.** Define the concepts, possible actions, and user/system responsibilities before choosing concrete screen details. Compare alternatives against goal, context and constraints. Move from scenarios and storyboards to low-fidelity wireframes, then to high-fidelity screens. Trace consequential changes from the wireframes to the evaluation evidence or design rationale.
4. **Show how tasks behave.** For each priority task, check that users can tell where they are, what they can do, what will happen next, and what has already happened. Use global hierarchy for structure and a network or flow diagram for actual transitions. Account for relevant alternative paths, back/cancel, validation, empty/loading/progress, success/closure, failure and recovery. Give controls functional labels, appropriate semantics, and predictable keyboard behavior.
5. **Evaluate and iterate.** Define success criteria before running a test. Pair observable performance measures with the user's reported experience. Record the task, starting state, participants or model assumptions, result, recommendation and retest outcome as applicable. Keep inspection findings, predictive estimates and participant observations identifiable. Run the course's heuristic evaluation for Phase 4. Use GOMS/KLM or Fitts' Law when a design question calls for a prediction.

## Check each screen and flow

- Apply the five screen-design principles together. **Group** related things, **order** them around the task and natural reading sequence, **align** for comparison and keyboard flow, use **whitespace** to separate, structure and highlight, and use **decoration** to clarify hierarchy or relationships. Apply typography, layout and color consistently. Use realistic content and the user's terminology.
- Check **Shneiderman's eight rules** for consistency, universal usability and accelerators, informative feedback, closure, error prevention, reversal, user control, and reduced short-term memory load. Check **Theo Mandel's three pillars** for user control, reduced memory load, and consistency. Preserve the user’s work through routine interruptions and recovery when relevant.
- Design for variation from the start. Apply the seven universal-design principles and check multiple ways to perceive information and operate controls. Use semantic structure, distinguishable focus, accessible names, sensible reading and focus order, readable contrast, and non-color cues. Check input methods and localization relevant to the audience and task. Compare target size and distance in the actual interaction context.
- Evaluate **Nielsen's ten heuristics** against real tasks. Give each finding a screen and step, evidence, primary heuristic, consequence, severity if applicable, and a specific recommendation. Test revised paths. See the course workbook and rubric in the [project and evaluation reference](references/project-evaluation.md).
